---
title: Migrations
description: Database migrations via raw PDO, independent of any ORM
---

Antares ships its own migration system built on raw PDO, with no ORM required. It works independently of the Eloquent bridge or any other ORM you choose to use.

## Connection

Migrations connect with these environment variables:

| Variable | Default |
|---|---|
| `DB_DRIVER` | `mysql` |
| `DB_HOST` | `127.0.0.1` |
| `DB_PORT` | `3306` |
| `DB_DATABASE` | (empty) |
| `DB_USERNAME` | (empty) |
| `DB_PASSWORD` | (empty) |

The connection string is built as `{DB_DRIVER}:host={DB_HOST};port={DB_PORT};dbname={DB_DATABASE}`, so **MySQL (`mysql`) and PostgreSQL (`pgsql`)** work. SQLite, SQL Server and Oracle use a different connection string format and can't connect yet.

## Creating a Migration

```bash
php bin/antares make:migration create_users_table
```

This creates a file in `database/migrations/` with a timestamp prefix, e.g. `2026_01_15_103000_create_users_table.php`. It contains a plain class (no namespace, no base class) whose name is the file name without the timestamp, in PascalCase:

```php
<?php

declare(strict_types=1);

final class CreateUsersTable
{
    public function up(\PDO $pdo): void
    {
        $pdo->exec("
            CREATE TABLE users (
                id INTEGER PRIMARY KEY AUTO_INCREMENT,
                name VARCHAR(255) NOT NULL,
                email VARCHAR(255) NOT NULL UNIQUE,
                created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
            )
        ");
    }

    public function down(\PDO $pdo): void
    {
        $pdo->exec("DROP TABLE IF EXISTS users");
    }
}
```

Keep the class name and file name in sync: the runner derives the class name from the file name. Class names must be unique across all migrations.

## Running Migrations

Run all pending migrations:

```bash
php bin/antares migrate
```

Migrations are tracked in a `migrations` table by file name. Already-run migrations are skipped, and everything run together is recorded as one batch.

---

## Rolling Back

Roll back the last batch of migrations:

```bash
php bin/antares migrate:rollback
```

Migrations in the last batch are rolled back in reverse order, calling each migration's `down()` method.

---

## How It Works

- Migration files live in `database/migrations/` (relative to where you run the command)
- Files are sorted by name, so the timestamp prefix sets the order
- The `migrations` table is created automatically on first run
- Each migration receives a raw `PDO` instance, set to throw exceptions on errors
- Migrations are not wrapped in a transaction: if one fails halfway, the ones before it stay applied and recorded

---

## ORM Independence

Migrations use raw PDO directly, so they work regardless of which ORM you use. Pair them with the Eloquent bridge, use a different ORM, or skip an ORM entirely.
