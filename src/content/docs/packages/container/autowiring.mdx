---
title: Autowiring
description: Automatic constructor injection via reflection
---

The container resolves classes and their entire dependency tree automatically. Concrete classes need no configuration.

## Basic Resolution

```php
use Antares\Container\Container;

class Logger {}

class UserService
{
    public function __construct(
        private readonly Logger $logger,
    ) {}
}

$container = new Container();
$service = $container->make(UserService::class);
```

Autowired classes are **not shared**: every `make()` call builds a new instance, and so does every class that depends on it. Register a class with `singleton()` or `scoped()` when it should be shared. See [Bindings & Singletons](/packages/container/bindings/).

## Nested Dependencies

The container walks the full constructor tree recursively:

```php
class Cache {}

class Repository
{
    public function __construct(
        private readonly Database $db,
        private readonly Cache $cache,
    ) {}
}

$repository = $container->make(Repository::class);
```

Both `Database` and `Cache` are resolved and injected automatically.

## How Each Constructor Parameter Is Resolved

| Parameter | Resolved as |
|---|---|
| Class or interface type (`Database $db`) | `$container->make(Database::class)`, **always**, even if it has a default value |
| Scalar or `array` type with a default (`int $perPage = 15`) | The default value |
| No type, with a default | The default value |
| Scalar without a default (`string $host`) | Error: register the class with `singleton()` and pass the value yourself |

```php
class Paginator
{
    public function __construct(
        private readonly Database $db,      // resolved from the container
        private readonly int $perPage = 15, // default used
    ) {}
}
```

:::caution
A nullable class parameter with a default, such as `?LoggerInterface $logger = null`, is still resolved from the container. If `LoggerInterface` is not bound, `make()` throws instead of passing `null`.
:::
